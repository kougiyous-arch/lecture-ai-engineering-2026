
# 第2回 解答

## 演習

### 使ったモデル・設定（`result.json` の `config` から）

モデルは `Qwen/Qwen3.5-0.8B` を使用した。LoRAによるファインチューニングを行い、主な設定は `lora_r=16`、`lora_alpha=32`、学習率0.0002、エポック数20、乱数シード42とした。

### 自分で学習を実行したか（`executed_training_myself`）

はい。Google ColabのT4 GPUを使用し、学習前後の評価とLoRAによる学習を実行した。

### 学習前後の評価結果

| 評価項目 | 学習前 | 学習後 |
|---|---:|---:|
| format_rate | 9.52% | 100% |
| content_rate | 0% | 90.48% |

### 退行した質問

なし。学習前に形式・内容ともに正解していた質問が、学習後に不正解となった例はなかった。

### 学習後に残った失敗と、その型

学習後は21問すべてでJSON形式を守れたものの、内容正解率は90.48%であり、2問が不正解だった。`result.json` には不正解となった2問の詳細が保存されていないため、失敗の型までは特定できない。ただし、セクション6ではFAQに根拠がない質問に対して、確認を求めずに断定する例が見られた。

### 知識を問う質問（セクション6）の結果（学習前の分類 → 学習後の分類）と気づいたこと

| 質問 | 学習前 | 学習後 |
|---|---|---|
| この講座の最終課題の締切はいつですか | format_error | asserted |
| 担当教員の名前は何ですか | format_error | needs_review |
| 次回の講義のテーマは何ですか | format_error | needs_review |
| 課題の提出期限はいつですか | format_error | asserted |

学習前は4問すべてでJSONの形式を守れていなかったが、学習後は形式を守れるようになった。担当教員の名前や次回の講義テーマについては、FAQに記載がないことを適切に判断できていた。一方、最終課題の締切については、FAQに記載された通常の課題提出期限を流用して断定していた。このことから、回答形式は学習できても、質問に対する根拠の有無を正確に判断できるとは限らないことが分かった。

### 学習で変わったこと・変わらなかったこと

学習前は、回答内容に関係なくJSONの必須キーが欠けるなど、指定した回答形式を守れないことが多かった。しかし、LoRAによる学習後は形式正解率が100%となり、内容正解率も90.48%まで向上した。このことから、ファインチューニングによって回答形式や特定の質問に対する回答方法を身につけさせられることが確認できた。

一方、FAQに記載されていない内容について、別の項目の情報を当てはめて回答する場合があり、根拠がない質問への適切な対応には課題が残った。したがって、ファインチューニングは回答形式の統一には有効だが、情報の正確性や根拠の判断まで保証するものではないと考えられる。

### [基礎]

#### 変えた設定やデータ

LoRAのランクを表す lora_r を16から4に変更し、再学習を行った。学習率（0.0002）とエポック数（20）は変更していない。

#### 結果（比較表や数字）

| 評価項目 | r=16 | r=4 |
|---|---:|---:|
| format_rate | 100% | 100% |
| content_rate | 90.48% | 100% |
| 最終Training Loss | 0.014008 | 0.013013 |
| 学習時間 | 224秒 | 221秒 |
| ステップ数 | 40 | 40 |
| エポック数 | 20 | 20 |

ランクを16から4に減らした結果、format_rateはどちらも100%であったが、content_rateは90.48%から100%に向上した。また、最終lossもわずかに減少し、学習時間も3秒短縮された。今回の結果では、ランクを小さくしても性能は低下せず、むしろ評価指標上は改善が見られた。

### [実装]

#### 変えた設定やデータ

FAQを講義の課題提出に関する内容から、ローカル5Gに関する内容へ変更した。総務省の「ローカル5G導入に関するガイドライン」を参考に、以下の5項目を設定した。lora_rは4で行っている。

1. ローカル5Gの概要
2. 利用可能な周波数帯
3. 無線局免許の必要性
4. 免許申請の標準的な処理期間
5. 屋内利用時に優先される周波数帯

GROUNDEDには、FAQの内容を異なる表現で質問するものを用意した。一方、UNGROUNDEDには、最大通信速度、通信距離、送信電力、MIMOレイヤ数など、ローカル5Gに関係するものの、今回のFAQには記載されていない情報を尋ねる質問を用意した。

#### 結果（比較表や数字）

| 評価項目 | 学習前 | 学習後 |
|---|---:|---:|
| format_rate | 0% | 100% |
| content_rate | 0% | 90.48% |
| both_rate | 0% | 90.48% |
| 評価対象数 | 21件 | 21件 |
| 最終Training Loss | - | 0.012194 |
| 学習時間 | - | 275秒 |
| 学習ステップ数 | - | 40 |
| エポック数 | - | 20 |

学習前は指定されたJSON形式で回答できず、内容正解率も0%だったが、学習後は形式正解率が100%、内容正解率が90.48%となった。

### [発展]

#### 変えた設定やデータ

講義の用語集58語から、各用語について2種類のQ&Aを生成し、計116件の学習データを作成した。これをFAQの代わりに用い、LoRAによるファインチューニングを行った。

評価には、用語集に収録された語を直接尋ねる5問、言い回しを変更した5問、用語集にない語を尋ねる3問の計13問を用意した。未登録語にはBLEUスコア、バッチ正規化、モデル蒸留を選び、用語集に記載がないことを確認した。

#### 結果（比較表や数字）

| 評価項目 | 学習前 | 学習後 |
|---|---:|---:|
| 用語集にある語（5問） | 2/5（40%） | 5/5（100%） |
| 言い換え質問（5問） | 1/5（20%） | 0/5（0%） |
| 用語集にない語（3問） | 0/3（0%） | 0/3（0%） |
| **合計（13問）** | **3/13（23.1%）** | **5/13（38.5%）** |

学習後は、用語集にある5語について、すべて定義文と完全に一致する回答が得られた。一方、言い回しを変更した質問では、正しい用語を回答できない場合が多く、学習前に正解していた質問でも不適切な回答が見られた。

---

### ファインチューニングが向く場面・向かない場面についての考察

ファインチューニングは、回答形式を統一したり、特定の質問に対する回答方法を学習させたりする場合に適していると考えられる。一方、学習データにない質問への対応や、情報の正確性が求められる場面では、誤った回答を生成する可能性がある。今回の結果から、LoRAのランクを大きくすれば必ず性能が向上するわけではなく、学習データや目的に応じて適切な設定を選ぶことが重要だと感じた。
